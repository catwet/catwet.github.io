CATWEB - INVENTARIO DE FUNCIONES EJECUTABLES
Auditoría estática de los catálogos de este repositorio; no es una especificación oficial de runtime.

ALCANCE Y MÉTODO
- Fuente primaria: 17 categorías JSON enumeradas en script/catalog-index.json, procesadas con BlockCatalog de catweb_script.py.
- Inventario: 138 entradas con nombre CSL único, contando eventos, acciones, condiciones, ciclos y declaración/retorno de funciones.
- Los nombres exactos son los nombres canónicos que expone el compilador CSL del proyecto. Los ejemplos se validan sintácticamente contra ese catálogo; no se ejecutaron dentro del juego Catweb.
- El repositorio contiene plantillas de referencia, no el runtime de Catweb. Donde no hay especificación adicional, el comportamiento se limita a la etiqueta visible y se indica expresamente.
- Las entradas l= y t= reproducen la etiqueta y el tipo de campo del JSON. t= es el tipo de control/campo observado, no necesariamente un tipo semántico documentado. Los valores de muestra no son restricciones ni garantizan ejecución.
- Las sintaxis abstractas usan cadenas entre <> como marcadores; los ejemplos son llamadas CSL con literales. Sustituye IDs, objetos, teclas y propiedades por referencias válidas del proyecto.
- Módulos derivados de los nombres CSL: hierarchy.json -> objects; looks.json -> ui; strings.json -> text; math-variables.json -> variables y math. No existe un archivo math.json independiente.
- No se listan como funciones: bloques repetidos "When website loaded..." de archivos de ejemplo no-events, comentarios, marcadores end/else, objetos visuales ni palabras reservadas. if/for/def/on son sintaxis CSL; no funciones de Catweb.
- No hay sobrecargas con el mismo nombre CSL en el catálogo compilable. Alias del compilador: log, warn y error equivalen a console.log, console.warn y console.error. Asignaciones x = v, x += v, x -= v, x *= v y x /= v son azúcar CSL de variables.set/increase_by/decrease_by/multiply_by/divide_by.

ENTRADAS DEL CATÁLOGO EXCLUIDAS POR NO SER FUNCIONES
- 16 plantillas top-level repetidas "When website loaded..." en JSON de módulos distintos de events; son andamiaje de los ejemplos, no eventos propios de esos módulos.
- 6 marcadores "end": hierarchy/25, input/25, logic/25, looks/25, loops/25 y tables/25. Son cierres estructurales.
- 1 marcador "else": logic/112. Es sintaxis de control, no una llamada.
- 4 bloques de comentario sin nombre ejecutable: functions/124, loops/124, network/124 y tables/124.
- En total, BlockCatalog contiene 27 variantes de plantilla sin nombre CSL; no se publican como funciones. Los bloques log de los módulos sí se incluyen porque tienen nombre CSL y campo ejecutable.

EJEMPLO REAL BASADO EN EL JSON ADJUNTO
El adjunto contiene un evento load, una variable, un split y una iteración de tabla. Esta representación CSL se compiló con el catálogo del repositorio:
on load:
    x = "hola como estan"
    text.split("{x}", " ", "textos")
    for tables.iterate_through_l_index_l_value("textos"):
        console.log("{l!value}")
El compilador genera también el cierre del ciclo; la prueba de compilación produjo un evento y cinco acciones. Esto no sustituye una ejecución dentro de Catweb.

NOTAS DE MÓDULOS
- cookies: info.md advierte que estas funciones son de pago y requieren que estén desbloqueadas.
- network: info.md advierte que Roblox puede filtrar datos no numéricos entre sitios; el repositorio no implementa ni garantiza codificación o entrega.
- events: info.md documenta las variables locales indicadas en las entradas de eventos correspondientes.
